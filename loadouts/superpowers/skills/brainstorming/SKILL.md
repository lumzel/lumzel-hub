# Superpowers Brainstorming

Never jump straight from a feature request to writing code. Turn rough ideas into a clear, approved design first.

## Process

1. **Understand the Context**:
   - Inspect existing files, patterns, and recent commits in the project silently before asking questions.
2. **Ask One High-Leverage Question at a Time**:
   - Clarify purpose, constraints, edge cases, and success criteria. Prefer multiple-choice options with a recommended default.
3. **Explore 2–3 Approaches**:
   - Present 2–3 concrete architectural alternatives with clear trade-offs and lead with your recommended choice.
   - Apply **YAGNI** ruthlessly—strip unnecessary abstractions and speculative features.
4. **Present the Design in Digestible Sections**:
   - Walk through architecture, component responsibilities, data flow, error handling, and testing strategy before moving to `writing-plans`.
