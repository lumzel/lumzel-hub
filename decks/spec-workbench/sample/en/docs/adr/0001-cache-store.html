Use Redis for Cache, Not In-Process Memory

Store the invoice read cache in Redis.

Context

The invoice service runs four instances. Traffic is read-heavy, and once an amount changes, no instance may serve a stale value.

Decision

✓ Where to store the cache?
RedisIn-process
→ Redis
Why: A single delete invalidates across all four instances.

Consequences

ConsequenceMitigation
One extra network hop per read (~1 ms)Acceptable against the 20 ms p95 target
Read path must stay up if Redis goes downFall back to DB on connection failure; covered in Ticket 01
