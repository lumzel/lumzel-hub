Invoice Read Cache

The invoice detail endpoint queries the DB on every request, hitting 120 ms p95 at peak. Add a Redis cache in front of reads and evict on write to stay under 20 ms p95.

Decisions

✓ Where to store the cache?
RedisIn-process
→ Redis
Why: Four instances run concurrently; in-process caches diverge and cannot be cleanly evicted on write.
✓ How long should the TTL be?
1 minute10 minutes60 minutes
→ 10 minutes
Why: A missed eviction stays stale at most 10 minutes; anything shorter drops hit rate below 60%.

Risks

Missing an eviction on any write path serves stale amounts. Ticket 03 adds a dedicated test for every write entrypoint.
