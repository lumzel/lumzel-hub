发票读取缓存

发票详情页每次都查库，高峰期 p95 到 120 ms。读路径前面加一层 Redis 缓存，写后删除，目标 p95 低于 20 ms。

决定

✓ 缓存放哪？
Redis进程内
→ Redis
为什么：服务有四个实例，进程内缓存各算各的，写后删除删不干净。
✓ TTL 多长？
1 分钟10 分钟60 分钟
→ 10 分钟
为什么：漏删一次最多错 10 分钟；再短命中率掉到 60% 以下。

风险

写路径只要漏删一处缓存，用户就会看到旧金额。工单 03 给每个写入口各配一条测试。
